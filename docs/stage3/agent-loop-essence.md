# Agent 循环的本质：所有 SDK 背后的共同内核

> 阶段 3 概念文档 | 配合 Task 3.1、3.2、3.3 阅读

---

## 1. 本质是什么

你会学 OpenAI Agents SDK、Claude Agent SDK、LangChain、CrewAI…… 它们看起来千差万别。

但剥开所有外衣，它们的核心都是**同一个东西**：

```
while 未完成:
    决策 = LLM(当前状态 + 可用工具)
    if 决策 == 调用工具:
        结果 = 执行工具
        更新状态
    else:
        返回最终答案
```

**你在阶段1 手写的那个循环，就是所有 Agent SDK 的内核。** 阶段3 你会看到各家 SDK 怎么包装这个内核，但内核本身你已经掌握了。

## 2. 为什么表面不同，内核相同

各家 SDK 的差异，都是在这个内核**外围**做文章：

| SDK | 表面差异 | 共同内核 |
|-----|---------|---------|
| LangChain | 用 AgentExecutor 封装循环 | while + LLM + 工具 |
| OpenAI SDK | 用 Runner.run() 封装循环 | while + LLM + 工具 |
| Claude SDK | 用 AgentLoop 封装循环 | while + LLM + 工具 |
| CrewAI | 多个 Agent 各自循环 | 每个都是 while + LLM + 工具 |

**它们都在做同一件事，只是封装方式、API 风格、附加功能不同。**

### 附加功能的本质

各家 SDK 比你手写的循环"多"出来的东西，本质都是**工程化能力**：

```
核心循环（大家都一样）：while + LLM + 工具

附加能力（各家不同）：
  + Handoff（任务交接）      → 多 Agent 协作
  + Guardrails（护栏）        → 输入输出安全检查
  + Tracing（追踪）           → 可观测性
  + Checkpoint（检查点）      → 状态持久化、恢复
  + Streaming（流式）         → 实时输出
  + Sandbox（沙箱）           → 安全执行代码
```

这些附加能力是 SDK 的差异化卖点，但**没有它们，Agent 循环照样能跑**（你的阶段1 代码就是证明）。

## 3. 心智模型：Agent SDK = 内核 + 工程化外壳

```
┌─────────────────────────────────────┐
│  工程化外壳（各家不同）              │
│  ┌───────────────────────────────┐  │
│  │  Handoff / Guardrails / Trace │  │  ← 差异化卖点
│  │  ┌─────────────────────────┐  │  │
│  │  │   Agent 循环（共同内核）│  │  │  ← 你阶段1 学的
│  │  │  while: LLM → 工具 → 更新│  │  │
│  │  └─────────────────────────┘  │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

**学阶段3 的正确姿势：**
- 不要被各家 SDK 的 API 吓住——内核你已经会了
- 重点关注它们的**外壳差异**（Handoff 怎么用、Guardrails 干嘛的）
- 对比它们怎么包装同一个内核

## 4. 嵌入式类比：内核 vs 板级支持包

你熟悉这个结构：

| Agent SDK 概念 | 嵌入式类比 |
|---------------|-----------|
| Agent 循环内核 | RTOS 内核（任务调度循环） |
| 各家 SDK 外壳 | 板级支持包（BSP） |
| Handoff / Guardrails | 中间件组件（文件系统、网络栈） |
| 同一内核，不同外壳 | 同一 RTOS 内核，不同厂商 BSP |

**FreeRTOS 内核在所有芯片上都是那套调度逻辑**，不同芯片厂商提供不同的 BSP（外设驱动、启动代码）。你换芯片要学新 BSP，但 RTOS 内核不用重学。

Agent SDK 一样：换框架要学新 API（外壳），但循环内核（你在阶段1 学的）不用重学。

## 5. 通过对比看透内核（阶段3 Task 3.3 的意义）

Task 3.3 让你用同一个任务（代码分析 Agent）在 3 个框架实现，然后写对比报告。**这个练习的价值不是"学会 3 个框架"，而是"看透它们背后是同一个内核"。**

做完你会获得一种能力：**看任何新框架，都能一眼看出它的内核循环在哪里、外壳加了什么。** 这种能力比精通某个框架值钱得多。

### 预期发现

| 维度 | 纯 Python | LangChain | OpenAI SDK |
|------|-----------|-----------|------------|
| 循环 | 你手写 for | AgentExecutor 内部 | Runner 内部 |
| 工具 | 手写 schema | @tool 装饰器 | @function_tool |
| 本质 | **完全相同** | **完全相同** | **完全相同** |

你会深刻体会到：**它们都在做 while(LLM → 工具)，只是代码组织方式不同。**

## 6. 两个真正有差异化的概念

虽然内核相同，但有两个概念是阶段3 才出现、且值得重点理解的：

### Handoff（任务交接）

**本质：一个 Agent 调用另一个 Agent 当工具。**

```
主 Agent："这个问题我不擅长，转给代码专家 Agent"
代码专家 Agent："我来处理" → 处理完把结果还给主 Agent
```

这是多 Agent 协作的雏形。内核还是循环，但循环里"调用的工具"变成了"另一个 Agent"。

### Guardrails（护栏）

**本质：在循环外面包一层输入/输出校验。**

```
用户输入 → [输入护栏检查] → Agent 循环 → [输出护栏检查] → 返回
              ↑ 拦截恶意输入              ↑ 拦截不当输出
```

这是安全工程。你的嵌入式背景会理解——就像通信协议里的帧校验、看门狗。Guardrails 防止 Agent 跑偏。

## 7. 常见误解纠正

### 误解 1："每学一个 SDK 都要从头理解"

**错。** 内核你已经会了（阶段1）。学新 SDK 只是在学"它怎么包装内核 + 加了什么外壳"。**这是为什么阶段1 让你手写循环——它是所有 SDK 的通用门票。**

### 误解 2："复杂的 SDK = 强大的 Agent"

**错。** SDK 复杂度 ≠ Agent 能力。一个用纯 Python（阶段1）写的精心设计的 Agent，可能比用重型框架堆出来的 Agent 更好。**Agent 的强弱取决于设计，不取决于用了多花哨的 SDK。**

### 误解 3："不同 SDK 的 Agent 能力有本质差别"

**基本错。** 只要内核是"while + LLM + 工具"，能力上限就主要由 LLM 决定，不是 SDK。SDK 影响的是**开发效率**和**工程化程度**，不是 Agent 本身的智能。

## 8. 一句话本质

> **所有 Agent SDK 背后都是同一个内核：while(LLM 决策 → 工具执行 → 状态更新)。各家差异都在外围外壳（Handoff、Guardrails、Tracing 等）。你在阶段1 手写的循环就是这个内核——掌握了它，所有 SDK 都只是"换了个包装"。**

## 9. 你将经历的代码，对应到这里

阶段3 你会写：

```python
# OpenAI Agents SDK
agent = Agent(name="...", instructions="...", tools=[...])
result = await Runner.run(agent, input="...")
#   ↑ Runner 内部就是 while(LLM → 工具) 循环
#   你看不到循环，但它在跑你阶段1 写的那套逻辑

# 对比阶段1 你手写的：
for i in range(5):
    response = client.chat.completions.create(tools=...)
    if response.tool_calls: 执行工具
    else: return 结果
#   ↑ 同一个内核，只是这里你亲手写出来
```

**对比这两个，你会获得"看透框架"的能力。**
