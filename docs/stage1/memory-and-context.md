# 记忆与上下文：LLM 的工作记忆模型

> 阶段 1 概念文档 | 配合 Task 1.3 阅读

---

## 1. 本质是什么

LLM 是**完全无状态**的。每次调用它，它都像失忆一样，只看到你这次发给它的内容。

你感觉到的"对话连贯"，其实是**你的代码每次都把完整历史重新发一遍**造成的错觉。LLM 本身没有任何跨调用的记忆。

理解这一点，就理解了 Agent 记忆的本质：**记忆不是 LLM 的能力，而是你的代码维护的数据结构。**

## 2. 为什么这是 Agent 的根本约束

### 工作记忆是有限的

每次调用 LLM，你能发给它的文本量有上限（上下文窗口）：

```
gpt-4o-mini:  128K token
智谱 glm-4:    128K token
claude:        200K token
```

看起来很大？但 Agent 每一轮循环都要**重发完整历史**：

```
第1轮：发送 1 条消息          （100 token）
第2轮：发送 3 条消息          （300 token）
第3轮：发送 5 条消息          （500 token）
...
第N轮：发送 2N-1 条消息       （可能爆掉）
```

更糟的是：**发得越多越贵、越慢。** 因为 LLM 要重新处理所有历史。

### 这是"内存约束"，嵌入式工程师秒懂

| LLM 的上下文窗口 | 嵌入式的 RAM |
|-----------------|-------------|
| 有限大小 | 有限大小 |
| 每次调用都要装下所有历史 | 每次任务要装下所有状态 |
| 超了就报错或截断 | 超了就 OOM 或栈溢出 |
| 必须管理（压缩/丢弃） | 必须管理（释放/复用） |

你处理过 RAM 只有几 KB 的 MCU 吧？那种"每个字节都要精打细算"的感觉，就是 Agent 处理上下文的感觉。

## 3. 两种记忆的本质区别

### 短期记忆（工作记忆）

**本质：本次对话内的消息列表。**

```python
messages = [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "我叫张三"},
    {"role": "assistant", "content": "你好张三"},
    {"role": "user", "content": "我叫什么？"},
]
# LLM 能答出"张三"，因为它在 messages 里看到了
```

**特点：** 精确、即时，但会撑爆上下文窗口。需要**截断或摘要**。

**类比：** 嵌入式里的 RAM——快但易失，断电（对话结束）就没。

### 长期记忆（持久记忆）

**本质：外部存储，跨对话存在。**

```python
# 对话 A：存下"用户叫张三"
save_to_file("用户偏好", "用户叫张三")

# 对话 B（几天后）：读出来
记忆 = load_from_file("用户偏好")
# → 注入到 prompt: "已知信息：用户叫张三"
```

**特点：** 持久、跨会话，但需要**检索**（怎么找到相关的记忆？）。

**类比：** 嵌入式里的 Flash/EEPROM——慢但持久，断电不丢。

## 4. 记忆管理的核心难题：信息取舍

你 RAM 不够时怎么办？删掉不重要的数据。Agent 记忆一样——**核心难题是"保留什么、丢弃什么"。**

### 短期记忆的取舍策略

```
策略1：滑动窗口
  保留最近 N 条，丢弃最老的
  优点：简单；缺点：可能丢掉重要早期信息

策略2：摘要压缩
  把老消息压缩成一段摘要
  优点：保留要点；缺点：压缩有损，可能失真

策略3：混合
  system 永远保留 + 最近 N 条原文 + 中间部分摘要
  生产环境常用
```

### 长期记忆的取舍策略

```
策略1：全量注入
  把所有记忆都塞进 prompt
  优点：简单；缺点：记忆多了就爆

策略2：关键词检索（Task 1.3 的做法）
  根据当前问题，找关键词匹配的记忆
  优点：省 token；缺点：不准

策略3：向量检索（阶段5 RAG 会学）
  把记忆变成向量，算相似度找最相关的
  优点：准；缺点：需要向量数据库
```

**所有策略的本质都是一样的：在有限的上下文窗口里，塞进"对当前任务最有用"的信息。** 这是个永远存在的工程权衡。

## 5. 常见误解纠正

### 误解 1："LLM 能记住我们之前聊过什么"

**错。** LLM 每次都是全新调用，什么也不记得。是你每次把历史重发给它，它"看起来"像记住了。一旦你不发历史，它立刻失忆。

**验证方法：** 同一个 LLM，你发 `[{"role":"user","content":"我叫什么"}]`（不带历史），它绝对答不出来。

### 误解 2："对话越长，LLM 越了解我"

**错，甚至相反。** 对话太长会触发截断——你的早期重要信息被丢掉了，LLM 反而"忘了"。而且长历史会让 LLM 注意力分散，回答质量下降。**不是越多越好，是"相关"才好。**

### 误解 3："记忆系统越复杂越好"

**错。** 很多场景滑动窗口就够了，别过度工程。先从最简单的开始，遇到问题再加策略。Anthropic 的经验：**大多数生产 Agent 用很简单的记忆策略，复杂的反而难维护。**

## 6. 一句话本质

> **记忆不是 LLM 的能力，是你维护的数据结构。短期记忆是会爆的 RAM，需要取舍；长期记忆是持久存储，需要检索。所有记忆管理的本质都是在有限的上下文窗口里，塞进对当前任务最有用的信息。**
