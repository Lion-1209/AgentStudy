# RAG 的本质：给无状态函数注入外部知识

> 阶段 5 概念文档 | 配合 Task 5.3、5.4 阅读

---

## 1. 本质是什么

RAG（Retrieval-Augmented Generation，检索增强生成）的本质一句话：

> **在调用 LLM 之前，先从你的资料库里"检索"出相关内容，塞进 prompt，让 LLM 基于这些内容回答。**

就这么简单。所有 RAG 框架、向量数据库、embedding 模型，都是在围绕这个核心做工程优化。

**更本质地说：RAG 是给"无状态、知识固化在训练数据里"的 LLM，临时注入"最新的、私有的、外部"的知识。**

## 2. 为什么需要 RAG（LLM 的知识缺陷）

LLM 有三个根本性知识缺陷，RAG 正是为了解决它们：

### 缺陷 1：知识是"冻结"的

```
LLM 的知识停在训练截止日（如 2024 年）
你问"2026 年的新技术"，它要么不知道，要么编造
```

RAG 解法：**实时检索最新资料**，LLM 基于检索到的最新内容回答。

### 缺陷 2：不知道你的私有数据

```
LLM 没见过你公司的内部文档、你的私人笔记
你问"我们公司的报销流程"，它无从得知
```

RAG 解法：**把你的私有资料做成可检索库**，问答时检索相关片段。

### 缺陷 3：容易"幻觉"（编造）

```
LLM 倾向于"流畅地回答"，哪怕不知道也会编
你问一个冷门事实，它可能一本正经地胡说
```

RAG 解法：**给 LLM 提供真实资料作为依据**，让它"照着资料答"而非"凭记忆编"。

**RAG 的核心价值 = 让 LLM 基于真实、最新、私有的资料回答，而不是凭冻结的训练记忆。**

## 3. 心智模型：RAG = 开卷考试

| RAG | 考试类比 |
|-----|---------|
| LLM（无 RAG） | 闭卷考试（只能凭记忆，可能记错/编造） |
| RAG | 开卷考试（带参考书，照着资料答） |
| 检索（retrieval） | 翻书找相关章节 |
| 向量数据库 | 参考书库 |
| Embedding | 知道"哪页和问题相关"的索引 |
| chunking（分块） | 书的章节划分 |

**最关键的洞察：** 开卷考试能不能答好，**取决于你能不能快速翻到对的页**。RAG 的质量上限，由"检索质量"决定——找错了资料，LLM 再强也答不好。

这就是为什么 RAG 工程的核心难点是**检索**，不是生成。

## 4. RAG 的完整流程（四个阶段）

```
① 准备阶段（离线，做一次）
   你的文档 → 切块(chunking) → 向量化(embedding) → 存入向量库

② 查询阶段（在线，每次问答）
   用户问题 → 向量化 → 在向量库找最相似的块

③ 生成阶段（在线）
   用户问题 + 检索到的块 → 拼成 prompt → LLM 生成答案
```

### 每个阶段的本质

**① Chunking（分块）= 把书拆成章节**

文档不能整个塞给 LLM（太长），要切成小块。

```
难点：块切多大？
  太大：一块包含太多信息，检索不精确，且费 token
  太小：语义不完整，上下文丢失
  经验：一块 200-500 字，有语义重叠
```

**② Embedding（向量化）= 给每块内容做"语义指纹"**

把文本变成一串数字（向量），**语义相近的文本，向量也相近**。

```
"北京天气" 的向量 ≈ "首都的气候" 的向量   （语义近）
"北京天气" 的向量 ≄ "Python 编程" 的向量   （语义远）
```

这就是为什么能用向量相似度找"语义相关"的内容——不是关键词匹配，是**语义匹配**。

**③ 向量检索 = 找最相关的块**

用户问题向量化后，和库里所有块比相似度，取最相关的几个。

**④ 生成 = 带着资料回答**

把检索到的块塞进 prompt：
```
"根据以下资料回答问题：
 资料1：...
 资料2：...
 问题：北京天气怎么样？"
```

LLM 照着资料答（开卷考试）。

## 5. 核心洞察：检索质量决定一切

这是 RAG 最重要的认知。**RAG 不是"LLM + 数据库"，而是"检索系统 + LLM"。**

```
RAG 质量分解：
  检索质量（找得准不准）   ← 决定上限，70% 的重要性
  生成质量（答得好不好）   ← LLM 决定，30% 的重要性
```

**如果检索找错了资料**（比如问天气，检索出来的是旅游攻略），LLM 再强也答不好——它只能基于错误资料答。

**所以 RAG 调优的重心是检索，不是生成。** 你会花大量时间在 chunking 策略、embedding 模型选择、检索召回率上，而不是调 LLM。

### 检索质量的衡量

```
召回率（Recall）：该找的相关资料，找全了吗？
精确率（Precision）：找出来的资料，真的相关吗？
```

RAG 工程就是在这两者间权衡，最大化"找到所有相关且不混入无关"的能力。

## 6. 嵌入式类比：RAG 像"查表 + 计算"

| RAG | 嵌入式 |
|-----|--------|
| LLM | CPU 的计算单元 |
| 向量库 | 查找表（LUT）/ Flash 里的数据表 |
| Embedding | 数据的索引/哈希 |
| 检索 | 按索引查表 |
| RAG 整体 | 查表得到数据 → 送给 CPU 计算 |

**核心相似点：** MCU 算复杂函数时，常常"查表"（LUT）而非实时算——表里存预计算结果，查到就用。RAG 一样——LLM 不"记住"所有知识，而是"查表"（检索资料）再处理。

**关键差异（必须注意）：**
- LUT 是精确查找（地址 → 固定值）
- RAG 是**语义模糊查找**（"北京天气" 可能匹配 "首都气候"）

这个模糊性是 RAG 的难点，也是 embedding 技术存在的理由。

## 7. 进阶：为什么 RAG 通常不 fine-tune

"给 LLM 注入知识"有两条路：RAG 和 fine-tune（微调）。为什么 RAG 通常更优？

```
RAG：
  ✓ 知识可随时更新（改资料库就行）
  ✓ 可控（能看到检索了什么）
  ✓ 便宜（不用重新训练）
  ✓ 通用（一个模型服务所有知识域）
  ✗ 受上下文窗口限制（一次塞不了太多资料）

Fine-tune：
  ✓ 知识"内化"进模型权重
  ✓ 不占上下文窗口
  ✗ 更新昂贵（要重新训练）
  ✗ 不可控（不知道模型学了什么）
  ✗ 容易遗忘（学了新的可能忘了旧的）
```

**业界共识：知识用 RAG，能力（风格、格式、技能）用 fine-tune。** 

这是个重要的概念区分：
- **知识**（事实、文档）→ RAG。因为知识要更新、要可控。
- **能力**（写作风格、输出格式、推理方式）→ fine-tune。因为能力要内化。

**别用 fine-tune 灌知识**——那是用昂贵的方法解决 RAG 能更好解决的问题。

## 8. RAG Agent（Task 5.4）：让检索变智能

基础 RAG 是"每次都检索"。**RAG Agent 进一步：让 Agent 自己决定要不要检索。**

```
基础 RAG：
  用户问题 → 总是检索 → 总是带资料回答
  问题：简单问题也检索，浪费；检索到的可能无用

RAG Agent：
  用户问题 → Agent 判断："需要查资料吗？"
    是 → 检索（把检索作为工具）
    否 → 直接回答
```

**本质：把"检索"封装成一个工具，给 Agent 用。** Agent 根据问题判断要不要查文档。这比基础 RAG 更聪明、更省。

这就是 RAG 和 Agent 的结合点——你在阶段1-4 学的 Agent 能力 + 阶段5 的 RAG = RAG Agent。

## 9. 常见误解纠正

### 误解 1："RAG 就是搜索 + LLM"

**太简化了。** 搜索是关键词匹配，RAG 是**语义匹配**。问"首都的气候"，关键词搜索找不到"北京天气"（没共同词），但 RAG 能找到（语义相近）。**embedding 带来的语义检索，是 RAG 区别于传统搜索的核心。**

### 误解 2："RAG 能 100% 准确"

**错。** RAG 会遇到：
- 检索不到该有的资料（召回不足）
- 检索到无关资料（精确不足）
- LLM 忽略检索资料，仍凭记忆答（"不听资料"）
- 资料本身矛盾或过时

**RAG 提升准确性，但不保证 100%。** 仍需评估和调优。

### 误解 3："资料越多越好"

**错。** 资料多 → 噪音多 → 检索更难找相关。**资料要"精而相关"，不是"多而杂"。** 数据清洗、去重、分块质量，比数据量重要。

### 误解 4："embedding 模型越高级越好"

**不一定。** 中文场景下，一些专门的中文 embedding（如智谱 embedding-3、bge）可能比通用的高级模型更好。**embedding 要和你的数据语言/领域匹配。**

## 10. 一句话本质

> **RAG = 在调用 LLM 前先检索相关资料塞进 prompt，本质是给无状态、知识冻结的 LLM 临时注入外部知识（开卷考试）。RAG 质量由检索决定（70%），不是生成。知识用 RAG、能力用 fine-tune。把检索做成工具给 Agent，就是 RAG Agent。**
